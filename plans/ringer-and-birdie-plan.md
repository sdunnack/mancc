# Golf League Tracker — Implementation Plan

## Context

A golf league uses Golf Genius to track weekend scores across two separate events. This app computes and displays:
- **Ringers**: each player's lowest score per hole (holes 1–18) across ALL rounds from both events combined starting 4/22/2026
- **Birdies**: per player, total birdie count and which holes they birdied

The scoreboard is public (no login required) and hosted on GitHub Pages. A GitHub Actions workflow runs on a schedule to fetch scores, compute results, and write a `scores.json` file that the static site reads. No database needed — compute directly from the Golf Genius API on each workflow run.

**Note on API access:** User does not have Golf Genius API credentials yet. The Python script uses a mock data fallback that activates automatically when no API key is set, so the full UI is usable immediately. Swap in real credentials later with zero code changes.

**Note on API docs:** API documentation can be found in documentation/golfgeniusapiv2.apib

## API Notes (from `documentation/golfgeniusapiv2.apib`)

- **Auth (read endpoints)**: API key is a URL path segment — `GET /api_v2/{api_key}/events/...`. No Authorization header needed for reads.
- **Key endpoint**: `GET /api_v2/{api_key}/events/{event_id}/rounds/{round_id}/tee_sheet` returns everything in one call: pairing groups, players, and scores. No separate course endpoint needed.
- **Score array**: 21-element array per player. Indices 0–17 = hole-by-hole scores, 18–19 = nine-hole subtotals, 20 = 18-hole total. Unplayed holes are `null`.
- **Par values**: Hardcoded in `fetch.py` — not read from the API.
- **Player identification**: Each tee sheet entry has `name`, `player_roster_id`, `external_id`, and `player_GGID`.
- **Player list**: Maintained manually in `fetch.py` (waiting on final roster). The tee sheet is filtered to only include players in this list, matched by name or `external_id`.

## Implementation Details

### `scripts/golf_genius/client.py`
- Reads `GOLF_GENIUS_API_KEY` from environment; if unset, sets `USE_MOCK_DATA = True`
- Real mode: `requests.get(f"https://www.golfgenius.com/api_v2/{api_key}/{path}")`
- Mock mode: returns fixtures from `mock_data.py` based on path string

### `scripts/golf_genius/api.py` — functions called by `fetch.py`
```
get_rounds_for_event(event_id) → list[GGRound]
get_tee_sheet(event_id, round_id) → list[GGPairingGroup]
  └─ each player in group has: name, player_roster_id, score_array (21 elements)
```

### `scripts/fetch.py`
```python
# Event IDs — hardcoded, these don't change
EVENT_IDS = ["<event_id_1>", "<event_id_2>"]

# Par values for holes 1–18
PARS = [4, 4, 5, 5, 3, 4, 4, 3, 4, 4, 4, 3, 4, 5, 5, 4, 4, 3]

# Player list — update when roster is finalized
PLAYERS = [
    "Last, First",
    # ...
]

# 1. For each event in EVENT_IDS: get_rounds_for_event
# 2. For each round: get_tee_sheet
# 3. Flatten tee sheet into list of (player_name, round_label, hole_scores[0:18])
#    filtering to only players in PLAYERS list
#    pars come from the hardcoded PARS constant
# 4. compute_ringers + compute_birdies
# 5. Write result to docs/scores.json
```

### `scripts/compute/ringers.py`
- Input: list of `(player_name, round_label, scores[18])` across all rounds/events; pars come from the hardcoded `PARS` constant
- Build map: `player_name → hole_index → min(score)` (skip `None` values)
- Eagle = `score <= par - 2`, birdie = `score == par - 1`
- Sort by total ascending; players with incomplete cards (any `None`) sort last
- Output includes per-player `rounds` list (all individual round rows) alongside the computed ringer `holes`

### `scripts/compute/birdies.py`
- Build map: `player_name → hole_index → count` where `score == par - 1`
- Also track `player_name → round_label → list[hole_index]` of birdied holes per round
- Sort by `total_birdies` descending
- Output includes per-player `rounds` list (which holes were birdied in each round) alongside the aggregate `birdiedHoles`

### `.github/workflows/update-scores.yml`
- Trigger: `schedule` (e.g., every hour on weekends) + `workflow_dispatch` for manual runs
- Steps: checkout → set up Python → install `requests` → run `python scripts/fetch.py` → commit & push `docs/scores.json` if changed
- Secrets used: `GOLF_GENIUS_API_KEY`

### `docs/index.html`
- On load: `fetch('scores.json')` → parse JSON → render two tabs
- **Ringers tab — player list view** (default):
  - One row per player showing their ringer scorecard (best score per hole across all rounds)
  - Cells color-coded:
    - Eagle (≤ par−2): gold
    - Birdie (par−1): red (golf convention)
    - Par: white
    - Bogey+: light gray
  - Clicking a player row expands (or navigates) to a **player detail view**
- **Player detail view**:
  - One row per round the player participated in, labeled with `roundLabel`
  - A final **Ringer** summary row showing the best score per hole
  - Cells in each round row that match the ringer score for that hole are highlighted (e.g. bold outline or distinct background) so you can see which round produced each ringer
  - Same color-coding as above applied to all cells
  - A back button/link returns to the player list
- **Birdies tab — player list view** (default):
  - Ranked list with player name, total birdies, and a badge per birdied hole; superscript count if birdied 2+ times (e.g. `7²`)
  - Clicking a player expands to a **birdie detail view**
- **Birdie detail view**:
  - One row per round, labeled with `roundLabel`, showing hole badges for every hole birdied in that round
  - A **Total** summary row at the bottom showing aggregate counts across all rounds
  - A back button/link returns to the player list
- Shows `lastUpdated` timestamp

```bash
cp .env.example .env

```

Enable GitHub Pages in repo settings: **Source → Deploy from branch → `main` → `/docs`**

The first run of the Actions workflow (or a manual `workflow_dispatch`) will populate `scores.json` and trigger a Pages redeploy.
